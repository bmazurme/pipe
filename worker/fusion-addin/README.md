# Add-in pipe для Fusion 360

Маленький add-in, который запускается **внутри Fusion 360** и даёт worker'у на этом же Mac три вещи: выполнить Python-скрипт
(Fusion API), сделать снимок модели и выгрузить файл (STEP/STL/F3D/IGES). Через него Claude на Mac строит и проверяет CAD-модели
для задач Lab с выбором «Fusion 360 на Mac» (`cad/vN/*.py` в репозитории проекта).

```
bridge ── задача Lab (Fusion 360 на Mac) ──► worker на Mac ──► claude CLI ──► fusionctl ──► add-in в Fusion (127.0.0.1)
```

## Безопасность — прочитайте до установки

- Add-in слушает **только 127.0.0.1** и требует токен. Токен генерируется при первом запуске и лежит в файле настроек (по умолчанию
  `~/.pipe-fusion/config.json`, см. `PIPE_FUSION_CONFIG` ниже; права `0600`) вместе с портом; по нему worker находит add-in. Запросы из браузера (с заголовком `Origin`) и с чужим `Host` отклоняются.
- Add-in **выполняет присланный Python-код с правами Fusion**. Это тот же уровень доверия, что у самого worker'а: он запускает
  Claude с `--dangerously-skip-permissions` (произвольные команды в оболочке) от имени пользователя macOS, под которым работает.
  Поэтому: **заведите отдельную учётную запись macOS без прав администратора**, залогиньтесь в неё с Fusion 360 и запускайте worker
  в ней. Не запускайте его от своей основной учётной записи с личными файлами, ключами и сессиями.
- Fusion требует графической сессии: учётная запись должна быть залогинена (быстрое переключение пользователей подходит), экран
  может быть заблокирован, но сессия не должна быть завершена.

## Установка

1. Fusion 360 установлен и хотя бы раз запущен под этим пользователем.
2. Из корня репозитория:
   ```bash
   worker/fusion-addin/install.sh          # копирует PipeFusion в каталог add-in'ов Fusion
   ```
   (`--link` — вместо копии ссылка, для разработки add-in'а; `--remove` — удалить.) После обновления репозитория запустите ещё раз.
3. В Fusion: **Utilities → Add-Ins → Scripts and Add-Ins** (Shift+S) → вкладка **Add-Ins** → **PipeFusion** → включите
   **Run on Startup** и нажмите **Run**. Add-in пишет `~/.pipe-fusion/config.json`.

   Путь к этому файлу меняет переменная `PIPE_FUSION_CONFIG` (полный путь к файлу; по умолчанию `~/.pipe-fusion/config.json`).
   Её читают обе стороны: add-in (куда записать порт и токен) и worker вместе с `fusionctl` (откуда их прочитать), поэтому значение
   у них должно быть одинаковым. Add-in — это Python внутри процесса Fusion, и он видит только окружение самого Fusion: `export` в
   профиле терминала до Fusion, запущенного из Dock или Launchpad, обычно не доходит. Задайте переменную для приложений сессии,
   например `launchctl setenv PIPE_FUSION_CONFIG /путь/к/config.json` (действует до перезагрузки), и перезапустите Fusion; worker'у
   задайте тот же путь в `EnvironmentVariables` его launch agent'а, а для `fusionctl` в терминале — через `export`. Если пути
   разойдутся, worker не найдёт add-in или add-in запишет файл туда, где его никто не читает.
4. Проверка (должен вернуться JSON с версией Fusion и именем документа):
   ```bash
   node worker/dist/fusion/fusionctl.js health
   ```

## Worker на Mac

См. раздел «macOS + Fusion 360» в [../README.md](../README.md): сборка, подключение кодом из bridge, launch agent. В bridge:
**Worker → Worker'ы → настройки этого worker'а → «Fusion 360 на этом компьютере»**; тогда задачи Lab с выбором
«Fusion 360 на Mac» уходят только ему.

## Что умеет `fusionctl`

Это то, что видит модель; можно пользоваться и руками.

| Команда | Что делает |
|---|---|
| `health` | жив ли Fusion, версия, активный документ |
| `info` | активный дизайн: тела (габариты, объём, масса), компоненты, параметры, единицы |
| `run <script.py> [--timeout SEC]` | выполняет скрипт внутри Fusion; печать и traceback возвращаются; код выхода 1 при ошибке скрипта |
| `screenshot <out.png> [--view iso\|front\|back\|top\|bottom\|left\|right] [--size WxH]` | снимок активного вида |
| `export <step\|stl\|f3d\|iges> <файл>` | выгрузка активного дизайна |

Скрипт пишется как обычный скрипт Fusion: функция `run(context)`, `adsk.core`/`adsk.fusion`. Размеры в API — **сантиметры**.
Код выхода: 0 — готово, 1 — ошибка скрипта, 2 — неверные аргументы, 3 — Fusion недоступен.

## Ограничения

- Скрипт выполняется в главном потоке Fusion, пока он работает, интерфейс Fusion занят. Если вышло время (`--timeout`), запрос
  завершается ошибкой, но сам скрипт может ещё выполняться — Fusion прервать его нельзя.
- Одновременно один запрос: worker берёт по одной задаче.
- Add-in не открывает документы из облака Autodesk и не сохраняет туда: работа идёт в новом локальном документе, результат — файлами.

## Разработка и тесты

Логика без Fusion (запуск скрипта, HTTP-сервер, конфиг) покрыта тестами на стандартной библиотеке Python (3.9+):

```bash
python3 -m unittest discover -s worker/fusion-addin/tests
```

Файл `fusion_ops.py` обращается к Fusion API и проверяется только в самом Fusion. Если после обновления Fusion какая-то операция
не работает, смотрите именно его.
