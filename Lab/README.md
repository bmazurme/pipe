# Lab

MVP оценки идеи: модульный конвейер «параметры → 3D-модель → масса/стоимость → расчёты →
STEP/STL/2D-чертёж» для хардварных проектов (катер, самолёт, …). Самостоятельный проект — не часть
npm-workspace'ов `pipe`, свой Python-стек, своя установка. Запускается руками, без worker'а
и bridge — см. `IMPLEMENTATION_PLAN.md` за тем, что дальше.

## Зачем так, а не иначе

`lab/core/` не знает, что такое корпус или крыло — только `Domain`, `PartSpec`
(солид + материал + режим массы) и общую математику (масса/стоимость/печать/экспорт/
бисекция). Всё специфичное для класса изделия лежит в `lab/domains/<name>/` и
регистрируется в `lab/core/registry`. Это сделано намеренно модульным: в проекте уже два
домена (`boat`, `aircraft`), и переход от катера к самолёту не потребовал ни строки правок
в `lab/core/` — только новый модуль домена и новый `project.yaml`.

## Установка

Нужен Python ≥3.10 (проверено на 3.14, macOS arm64).

```bash
cd Lab
python3 -m venv .venv
.venv/bin/pip install -e .
```

## Запуск

```bash
.venv/bin/python -m lab run projects/rc-boat-demo
.venv/bin/python -m lab run projects/rc-plane-demo
.venv/bin/python -m lab run projects/formula-450   # реальный проект, не демо — см. его project.yaml
```

Каждый запуск: собирает геометрию из `project.yaml`, считает массу/стоимость каждой части,
прогоняет расчёты домена, экспортирует STEP+STL+DXF-чертёж (3 вида) в
`projects/<name>/export/` и пишет туда же `results.json`. Ничего из этого не коммитится в git —
сгенерированные файлы в `.gitignore` (пересобираются из `project.yaml`+кода, как `dist/` у
обычного пакета). Но каждый запуск **также** дописывает строку в `projects/<name>/history.jsonl`
— это уже не регенерируемый артефакт, см. раздел «История и факт» ниже.

## История и факт (`lab stats` / `lab measure`)

Каждый `lab run` дописывает «расчётную» запись в `projects/<name>/history.jsonl` — не
перезатирает, а копит: результаты всех прогонов, не только последнего. Когда что-то реально
напечатано/измерено — вес, скорость на воде, что угодно числовое — записывается рядом:

```bash
.venv/bin/python -m lab measure projects/rc-boat-demo total_mass_kg=0.95 --note "взвешено после печати"
.venv/bin/python -m lab stats projects/rc-boat-demo
```

`stats` сравнивает последний расчёт с последним замером по каждой метрике (любое число из
`results.json`, включая вложенные расчёты домена — `hydrostatics.waterline_transom_mm` и т.п.):

```
метрика                           прогонов  замеров   расчёт (посл.)   факт (посл.)   разница
total_mass_kg                            2        1           1.093           0.95    -13.1%
hydrostatics.waterline_transom_mm        2        1              30             24    -20.0%
```

В отличие от `export/`, `history.jsonl` **не** в `.gitignore` — замер нельзя пересчитать
заново, в отличие от STEP/STL, так что это такие же настоящие данные, как любой другой файл
проекта, и должны коммититься. Домен-агностично: модуль (`core/stats.py`) просто собирает
числа из `results.json`, не зная, что такое `hydrostatics` или `wing_loading`.

## Структура проекта (`project.yaml`)

```yaml
name: "Название"
domain: boat            # должен быть зарегистрирован в lab/domains/__init__.py
params: {...}           # всё, что нужно build()/calculators данного домена — своя схема у каждого домена
targets: {...}          # произвольные цели для сравнения человеком (в отчёт, не в расчёт)
purchased_bom:          # покупные компоненты, не создаются CAD'ом
  - part: "..."
    source: purchased
    qty: 1
    unit_cost_rub: 950
    unit_mass_kg: 0.075
```

## Что в MVP честно посчитано, а что — заглушка

| Что | Статус |
|---|---|
| Геометрия (лофт, объём, площадь, bbox, STEP/STL экспорт) | Реальный OCCT-движок (build123d/OCP) — не заглушка |
| 2D-чертёж (3 вида, hidden-line removal, DXF) | Реальная проекция той же солид-модели (`build123d.Drawing`+`ExportDXF`) — **без** размерных линий и рамки чертежа, см. `lab/core/geometry.py:export_drawing` |
| Масса/стоимость из материала (плотность×объём либо площадь×толщина для оболочки) | Реальная формула, каталог материалов — плейсхолдер (см. `lab/core/materials.py`) |
| Гидростатика катера (осадка **и дифферент** одновременно, по ЦТ — не только ровный киль) | Порт из реального проекта RC-катера (`hydrostatics_v13.py`, см. `IMPLEMENTATION_PLAN.md`), на реальной геометрии через предпосчитанную таблицу площадей по станциям (`core/geometry.py:station_area_profiles`) |
| Скорость катера | Порт метода Савицкого (1964) + реальная электрическая модель мотор/ESC/АКБ (`planing_v13.py`+`speed_powertrain.py`), не Крауза — на скалярных параметрах (не на геометрии корпуса) |
| Время/стоимость печати | Константная производительность (см3/час) — **не** реальный слайсер, см. `lab/core/printing.py` |
| Крыло самолёта | Плоская пластина вместо профиля — геометрия-плейсхолдер, доказывает архитектуру, не несёт аэродинамического смысла |
| Нагрузка на крыло (wing loading) | Реальная, стандартная формула |
| Прочность (FEM) | Отсутствует в MVP — следующий шаг, см. `IMPLEMENTATION_PLAN.md` |
| История расчётов/замеров, расчёт-vs-факт | Реально работает (`core/stats.py`, `lab stats`/`lab measure`) — простой append-only JSONL, без БД/сервера |

## `formula-450` — сверка на реальном проекте, не демо

`projects/formula-450` — не придуманные числа: геометрия/масса/ЦТ/редан/привод взяты из
реального, уже летающего (точнее, плавающего) RC-катера «Формула 450» (репозиторий `boat-rc`,
не часть `pipe`) — см. комментарий в начале его `project.yaml` за источниками каждого числа.
Цель — не повторить его корпус (у Lab нет редана/горба/переменного деадрайза, см. ограничения
ниже), а проверить **портированные формулы** на реальных входных данных:

- **Скорость сошлась хорошо**: 73.4 км/ч против эталонных 74.8 км/ч (той же модели, не замера
  на воде — реальные заезды показали лишь 8–18 км/ч из-за диагностированного проскальзывания
  винта, не мощности). Это ожидаемо: `planing_speed()` считает по скалярным параметрам
  (полуширина, деадрайз, позиция редана, мотор) — не трогает геометрию корпуса вообще.
- **Гидростатика разошлась заметно**: при принудительно той же массе (850 г) и том же ЦТ
  осадка на ровном киле — 25.7 мм у Lab против 31.3 мм у реального катера (≈18%), а дифферент
  при том же ЦТ — 2.95° против ≈0.67°. Это не баг решателя (ЦТ=ЦБ сходится точно, механизм
  работает) — это разная геометрия: упрощённый 5-станционный корпус Lab (без редана, с
  одинаковым деадрайзом по всей длине, с «запечатанной» палубой) распределяет объём иначе, чем
  настоящий корпус. `hydrostatics()` интегрирует реальную форму — и оказывается ровно настолько
  точна, насколько точна сама форма.
- Отдельно: собственный упрощённый корпус Lab, подогнанный под габариты «Формулы 450»
  (450×139×62мм), весит 394 г против реальных 230 г — тоже разница формы (без вырезанного
  кокпита, с равномерной толщиной), не ошибка материала/плотности.

Это и есть честный ответ на вопрос «работает ли перенесённая физика» — да, где она не зависит
от формы; там, где зависит, точность = точности геометрии, и это теперь измерено, а не
предположено.

## Как добавить новый домен (например, автомобиль)

1. `lab/domains/car/__init__.py`, `geometry.py`, `calculators.py` — по образцу `boat`/`aircraft`.
2. `geometry.py`: функция `build(params) -> BuildResult`, возвращает `PartSpec` на каждую именованную часть.
3. `calculators.py`: функции `(context: CalcContext) -> dict`, используют `context.build`, `context.mass_kg`, `context.total_mass_kg` и т.д. — никогда не трогают файлы напрямую.
4. В `__init__.py` — класс `Domain` с `name`, `build()`, `calculators`, и `register(...)` на модуле.
5. Добавить импорт в `lab/domains/__init__.py`.
6. `projects/<name>/project.yaml` с `domain: car`.

Ничего в `lab/core/` не меняется ни на одном из этих шагов — это и проверялось при
добавлении `aircraft`.

## Известные ограничения MVP (не баги, осознанно не сделано)

- Нет FEM/прочности, нет CFD — см. план.
- Нет интеграции с bridge/worker/GitLab — запускается только руками.
- Каталог материалов/констант — ориентировочные числа, не прайс поставщика.
- Один геометрический «архетип» формы на домен (одна форма корпуса, одна форма крыла; без
  редана, без переменного деадрайза) — расширение числа параметров формы — фаза 2. Насколько
  это важно для гидростатики — измерено в разделе `formula-450` выше, не предположено.
- `hydrostatics()`/`planing_speed()` домена `boat` теперь требуют `params.lcg_mm`; у Lab
  по-прежнему нет расчёта ЦТ по BOM-с-позициями (это CG-калькулятор отдельно, не перенесён) —
  `lcg_mm` задаётся готовым числом в `project.yaml`, как и в исходном проекте (там ЦТ считает
  отдельный скрипт `cg_v13.py`, тоже не связанный с гидростатикой напрямую).
- `planing_speed()` дополнительно требует параметры силовой установки
  (`motor_kv`, `motor_resistance_ohm`, `battery_voltage_v`, `motor_max_current_a` — см.
  `lab/domains/boat/calculators.py`); без редана (`redan_x_mm`) считает как одну сплошную
  поверхность — обычный, не ступенчатый случай метода Савицкого.
- `domain.build()` у `boat` строит ровно одну именованную часть (`hull`) — у реального катера
  печатается несколько отдельных деталей (крышка, лотки, моторама); `formula-450` учитывает их
  массой/стоимостью через `purchased_bom` (`source: printed`), не отдельной геометрией.
