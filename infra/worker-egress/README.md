# Фильтр исходящего трафика worker (S1, п. 3)

`claude --dangerously-skip-permissions` исполняет всё, что написано в задаче (или в отравленном issue). Контейнер worker поэтому считается враждебным:
он должен выходить в интернет и **не должен** видеть ничего дома — админку роутера, NAS, Postgres на white, sshd самой платы.

Проверено на red 2026-11-27 (до фильтра): контейнер на сети `docker0` соединяется с `192.168.50.12:22` (sshd платы) и с роутером `192.168.50.1`.
Всё, с чем worker говорит по делу — публичный адрес bridge, VPN-серверы, AI-провайдеры, GitHub/GitLab, — публичное; у работающего worker все
соединения шли на публичные IP.

## Что делает

Одна цепочка `PIPE-WORKER-EGRESS`, подключённая дважды:

- из `DOCKER-USER` — трафик, который контейнер шлёт **через** плату (LAN, соседние контейнеры);
- из `INPUT` — трафик **к самой плате** (sshd, всё, что слушает на её адресах); `DOCKER-USER` его не видит.

Внутри: ответы на входящие соединения пропускаются (страница Portainer на blue); затем исключения из `EGRESS_ALLOW`; затем отказ
(`icmp-admin-prohibited`) для `10/8`, `172.16/12`, `192.168/16`, `169.254/16` и `100.64/10`. Публичные адреса в цепочке не упоминаются — они проходят.
Отказ быстрый (`EHOSTUNREACH`, а не зависание), и счётчики показывают, сколько раз что-то стучалось в LAN.

Правила накладываются на всю сеть `docker0`: на ней живут worker'ы и (на blue) Portainer. Portainer'у исходящие в LAN не нужны.

## Установка (по одной плате)

```bash
scp -r infra/worker-egress pi@192.168.50.12:~/
ssh -t pi@192.168.50.12 'sudo bash ~/worker-egress/install.sh && sudo /usr/local/lib/pipe-worker-egress/worker-egress.sh verify'
```

`install.sh` ставит скрипт, сервис (при загрузке, после Docker) и таймер: каждые 5 минут правила накладываются снова — идемпотентно, так что сброс
файрвола или перезапуск Docker лечится сам. `verify` запускает одноразовый контейнер из образа worker и пробует роутер, саму плату и `1.1.1.1:443`:
первые два должны быть закрыты, третий открыт.

После установки на плате с worker'ом проверьте на деле: запустите задачу («Выведи hello и список файлов») — worker должен получить её и вернуть результат,
heartbeat на странице Worker не пропадает.

## Команды

| Команда | Что делает |
|---|---|
| `worker-egress.sh apply` | наложить правила (идемпотентно) |
| `worker-egress.sh check` | код 0 — на месте, 1 — нет; молча (его спрашивает агент платы, плитка «Дрейф») |
| `worker-egress.sh status` | на месте ли, и сколько попыток в каждую частную сеть уже отклонено |
| `worker-egress.sh verify` | реальная проверка одноразовым контейнером |
| `worker-egress.sh remove` | снять правила |

## Исключения и откат

Нужен частный адрес — `EGRESS_ALLOW="192.168.50.5/32"` в `/etc/pipe-worker-egress.env`; следующий запуск таймера (или `systemctl start pipe-worker-egress`) его применит.

Откат: `sudo systemctl disable --now pipe-worker-egress.timer pipe-worker-egress.service && sudo /usr/local/lib/pipe-worker-egress/worker-egress.sh remove`.

## Чего это не закрывает

- IPv6: у сети `docker0` IPv6 выключен (`EnableIPv6=false` на всех трёх платах), поэтому контейнер частных IPv6-адресов не видит. Включите IPv6 у Docker — добавьте и `ip6tables`.
- Другие сети Docker (overlay `bridgew_worker-net` и т.п.): правило про сеть `docker0`. worker'ы в Swarm-стеке сюда не попадают; сейчас там только `vpn-client`.
- Утечка через публичные адреса: worker по-прежнему может отправить что угодно на любой публичный адрес. Это ограничивается тем, что в контейнере нет секретов, кроме токена Claude и ключа worker.

Тесты: `bash infra/worker-egress/test.sh` (фейковые `iptables` и `docker`, 36 проверок; в CI).
