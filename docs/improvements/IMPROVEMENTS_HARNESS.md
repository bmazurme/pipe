## Где harness сейчас

`harness/src/status.ts` (`pipe-status`) — по умолчанию read-only отчёт, с опциональными `--pull`/`--retry`/`--publish` для выполнения действия (2.3, всегда с подтверждением). Он читает 4 локальных JSON-файла (`.sync-state.json`, `.sync-agent-state.json`, `.gitlab-worker-state.json`, `subscription-state.json` из reports), сводит их по ключу `projectId:iid`, выводит статус на каждую задачу (`deriveStatus`), помечает зависшие задачи (`--stale-after`) и умеет `--json`, `--filter`, `--watch`. Ненулевой код выхода можно использовать как health-check.

Чего ему не хватает, чтобы быть помощником:

- **Он видит только одну машину и только локальные файлы, по умолчанию.** Задачи worker (`jobs` в Postgres), статус worker (heartbeat), посылки в storage и состояние issue в GitLab (открыта/закрыта, MR, пайплайн) все теперь видны под опциональным `--live` (1.1 — bridge, 1.2/1.3 — GitLab, независимо друг от друга) — просто не включено по умолчанию. Чат по-прежнему не видно совсем — это не в scope ни одного из пунктов 1.x.
- **Он теперь умеет действовать, под `--pull`/`--retry`/`--publish` (2.3).** Раньше для каждой задачи только печаталась команда (2.1); теперь её можно выполнить прямо отсюда, с подтверждением.
- **Он теперь сообщает сам, под `--notify` (3.1).** Раньше `--watch` только перепечатывал весь отчёт, ничего не говоря о том, что изменилось.
- **У него нет памяти.** Есть только текущий снимок, а истории по задаче (когда ушла, сколько ехала, какая модель, сколько попыток) нет.
