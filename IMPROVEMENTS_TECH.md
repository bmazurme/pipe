## Предлагаемый порядок

Исторический ход работы (недели 1–4 из первой версии этого плана) выполнен
почти целиком — см. «Статус выполнения» выше. Ниже — пересобранный порядок
для того, что реально осталось, по актуальному приоритету, а не по
хронологии исходного анализа:

1. **5.1 — единый npm workspace, часть 2 (`reports`).** `sync`/`worker`
   сделаны (см. их строку в таблице выше) — остаётся `reports`, самая
   рискованная часть (свой вложенный workspace + CWD-чувствительный
   Vite/vitest), сознательно вынесенная в отдельный заход. `bridge`
   по-прежнему вне плана 5.1 целиком — не упоминался в исходной формулировке
   задачи, и те же риски (плюс production-деплой) делают его ещё менее
   подходящим кандидатом без отдельного обсуждения.
2. **2.1 — общий HTTP-клиент bridge + общий GitLab-клиент** (P1, не начат).
   Теперь на это можно опереться на уже готовый контракт из 2.2
   (committed OpenAPI + сгенерированные типы в `@pipe/protocol/bridge-api-types`,
   которые пока не использует ни один потребитель) — первый клиент,
   который стоит на них завести, закрывает сразу оба пункта.
3. **4.3 — тесты на reports `subscription/handler.ts`** (P1, частично).
   Единственный настоящий пробел в тестах, оставшийся из исходного списка —
